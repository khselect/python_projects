## 1. 한 줄 정의와 범위

> **매크로 국면으로 큰 자금의 방향을 먼저 읽고**, 실적 발표가 예정된 종목을 **관심 그룹 단위**로 묶어, 과거 실적 반응과 그룹 누적 수익률을 보여주고, 다가오는 실적의 반응을 **확률 분포**로 예측해 **위험관리형 참고 정보**를 무료로 공개한다. **투자자문이 아니라 누구에게나 같은 정보를 보여주는 정보 서비스**다.

**하는 것**
- 지표·그래프마다 ⓘ 초심자 가이드 (툴팁 + 가이드 페이지)
- 네 화면을 매크로 → 그룹 → 종목 순으로 겹친 **종합 판단**과, 사이트 데이터만 근거로 답하는 **로컬 sLLM 해설**
- 주요 매크로 지표의 **수준보다 방향 전환**을 추적해 국면 판정, 자산군별(주식 롱·숏, 채권, 원자재, 달러·현금) 가이드
- 실적 캘린더를 **관심 그룹**별로 묶어 보기
- 그룹의 연도×월 누적 수익률, 실적일 정렬 누적 초과수익률(CAR)
- 종목·그룹 단위 다음 날 반응 분포, 5·21·63일 누적 분포
- 보정 관문을 통과한 모델에 한해 규칙 기반 가이던스

**하지 않는 것 (비목표)**
- 실시간 시세, 장중 매매 신호
- 사용자별 1:1 맞춤 자문 (§12 규제 참고)
- 유료 LLM API를 런타임에 부르는 기능 (AI 해설은 로컬 sLLM으로 한정)
- 사용자 보유 자산을 받아 개별 종목·비중을 추천하는 기능

## 2. 설계 원칙 — 토큰 예산 우선

이 프로젝트에서 LLM 토큰은 서버 비용보다 먼저 관리해야 할 자원이다.

1. **집계·통계·시뮬레이션은 전부 코드로 한다.** LLM은 숫자를 만들거나 옮기지 않는다.
2. **토큰 비용은 사용자 수가 아니라 이벤트 수에 비례하게 만든다.** LLM 결과는 이벤트당 한 번 만들어 캐시하고 모든 사용자가 공유한다. 페이지 조회 1회당 토큰 = 0.
3. **게시물은 사전 계산된 정적 JSON이다.** 화면은 JSON을 읽어 그리기만 한다. 슬라이더 미리보기 같은 대화형 계산은 브라우저 JS(웹 워커) 또는 `@st.fragment`로 처리한다.
4. **Claude가 데이터를 읽어야 할 때는 요약본만 읽는다.** 파이프라인이 `digest.md`(목표 2,000토큰 이하)를 만들고, Claude는 그것만 읽는다. Alpha Vantage MCP로 Claude가 시세를 직접 조회하는 방식은 개발 중 확인 용도로만 쓴다.
5. **로컬 sLLM은 토큰 비용 0이지만 연산 비용이 있다.** Mac mini 한 대의 처리량이 곧 동시 사용자 한도다. 자주 묻는 질문은 하루 한 번 미리 생성하고, 자유 질문만 실시간으로 처리한다.
6. **LLM이 없어도 동작한다.** 모든 LLM 기능에는 템플릿 대체 경로가 있다.

### Pro 플랜과 API의 구분
- **개발**: Claude Code를 Pro 계정으로 사용. 대화와 Claude Code가 같은 사용 한도를 공유한다.
- **앱 런타임**: 게시한 앱이 서버에서 Claude를 호출하려면 **API 키(Console, 별도 과금)**가 필요하다. Pro 구독에는 API 사용이 포함되지 않는다.
  - 출처: https://support.claude.com/en/articles/9876003
- 결론: **유료 API 호출 0회로 설계**한다. 가이던스 유형 태깅과 AI 해설은 로컬 Ollama(gemma3)로 처리하고, Claude(Pro)는 개발과 태깅 결과 검수 보조에만 쓴다.

## 7. 모델 요약

검토서 v0.1 §방법론을 따른다. 추가분만 적는다.

### 7.0 태그 없는 기본 모델 (50종목 공통)
- 각 종목의 과거 실적 반응(초과수익률)에 **3성분 스튜던트 t 혼합분포를 EM으로 적합**해 강세·중립·약세 시나리오의 확률·평균·표준편차를 추정한다.
- 표본이 적은 종목은 같은 산업 그룹 5종목의 반응을 함께 써서 축소 추정한다(경험적 베이즈, κ = 5).
- EPS 서프라이즈 부호는 시나리오 확률의 보조 변수로만 쓴다.
- 태그가 검수된 종목은 태그 기반 시나리오로 바꾸고, 백테스트로 비교해 더 잘 맞는 쪽을 쓴다. 화면에 "태그 기반 / 자동 추정" 표시.

### 7.1 그룹 수익률 (F12)
- 그룹 일수익률 = 구성 종목 수익률의 가중 평균 (동일가중 기본, 시총가중 옵션), 월초 리밸런싱
- 월·연 누적은 일수익률 복리 누적

### 7.2 그룹 이벤트 CAR (F13)
- 반응일을 t=0으로 맞추고 AR = R − α − β·R_m (벤치마크: 그룹 ETF 또는 SPY)
- 그룹 CAR = 이벤트 평균, 밴드 = 이벤트 간 25~75 백분위

### 7.3 공통요인 시뮬레이션 (F14)
```
AR_i = β_i · F_g + ε_i,   F_g ~ 그룹 공통 충격,  ε_i ~ t_ν(0, σ_i)
```
- 종목 반응을 독립으로 합치면 그룹 꼬리위험을 과소추정한다 (공통원인고장 β-factor와 같은 구조)
- 순차 갱신: 선행 발표 종목의 유형이 확인되면 후행 종목의 π_k를 베이즈 갱신

### 7.4 가이던스 레이어 (F15)
| 단계 | 출력 | 조건 |
|---|---|---|
| 랭킹 | E[초과수익]/CVaR₅% 순 정렬 | 항상 표시 |
| 조건부 표시 | 미리 정한 통계 조건 충족 시 "위험 신호" 배지. 행동 문구 없음 | 보정 관문 통과 모델만 |
| 비중 제안 | — | **하지 않음 (§12)** |

**보정 관문**: Brier < 0.25, 90% 구간 포함률 85~95%, 표본 ≥ 20건 (`config/model.yaml`). 미통과 시 회색 "참고용".
**규칙 성과 검증**: 거래비용 포함 백테스트를 따로 둔다.

### 7.5 매크로 국면 판정 (F16·F17)

- **국면 점수** = 10개 신호의 합(−10~+10), 동일 가중 (v0.21; v0.20까지 매크로 6개 −6~+6).

- **급변 규칙**: VIX ≥ 30 또는 나스닥100 고점 대비 −20% 이하면 점수와 관계없이 "위험회피(급변)", 확정 기간 없음. 해제는 VIX < 25이고 나스닥100 −15%보다 회복이 5거래일 연속(v0.22 히스테리시스).
- **검증(v0.21~)**: 2007년 이후 S&P 500 **52주 고점** 대비 −15% 구간의 탐지 지연(−10% 도달일 대비)과 오경보율(위험회피 진입 뒤 63거래일 낙폭 −7%보다 얕음)을 6개 안과 10개 안으로 비교(`pf.macro.evaluate`). 경계 조정은 이 결과와 근거를 함께 기록.
- **변화 표시**: 상대 비교 기준(기본 6개월 전)의 상태와 현재 상태를 나란히, 지표마다 마지막 전환일.
- **자산군 가이드(F17)**: 같은 국면 날짜들의 이후 63거래일 수익률 중앙값, 상승 확률, 표본 수. 배지: 중앙값 > 0 이고 상승 확률 ≥ 55% → "과거 강세 우위", 중앙값 < 0 이고 ≤ 45% → "과거 약세 우위", 그 외 → "뚜렷한 차이 없음".
- **미래 정보 누수 방지**: GDP 등은 발표일 기준으로만 반영.
- **검증**: 부트스트랩 신뢰구간, 표본 20구간 미만은 "참고용".
- **토큰**: LLM 호출 0회.

### 7.6 종합 판단 (F19)

| 층 | 결정하는 것 | 입력 | 방향 값 |
|---|---|---|---|
| 1 매크로 | 어느 자산군이 과거 같은 국면에서 강했나 | 국면 점수, 자산군 가이드 | ≥ +3 → +1, ≤ −3 → −1, 그 외 0 |
| 2 그룹 | 관심 그룹별 실적 시즌 통계 | 그룹 21일 기대 초과수익, 90% 구간, 보정 배지 | 기대값 부호 (참고용이면 0) |
| 3 종목 | 다가오는 실적의 개별 위험 | P(하락), 90% 구간 하단, CVaR | P(하락) ≥ 60% 또는 하단 ≤ −15% → −1 |

- **상위 층이 하위 층보다 우선**. 일치·충돌을 표시하고 점수를 평균내지 않는다.
- 출력 문구는 서술형 고정 템플릿(LLM 미사용).
- **구현 메모 (v0.16, `pf.synth.rules`)**: 보정 관문(F10)이 v2라 지금은 모든 그룹이 참고용 → "참고용이면 0"을 그대로 쓰면 그룹 층이 항상 0이므로, 21일 CAR 중앙값 ±0.5% 중립 구간을 두고 부호를 쓰되 "참고용"을 표시한다. 종목 층 +1 조건(P(상승) ≥ 60% 이고 90% 하단 > −15%)은 −1 조건과 대칭. 계산하지 않은 과거 성과(자산군 가이드 F17 전)는 문구에 넣지 않는다. 금지어 검사 `check_wording`.

## 8. LLM 사용 지점과 토큰 예산

| 용도 | 단계 | 빈도 | 입력 | 출력 | LLM 없을 때 |
|---|---|---|---|---|---|
| 가이던스 유형 태깅 | 1 | 이벤트당 1회 (월 약 17건, 과거 약 600건) | 가이던스 문단 (~1,500토큰) | JSON 태그 (~80토큰) | 태그 없는 기본 모델 |
| 그룹 주간 요약 문장 | 2 | 주 1회 | `digest.md` (~2,000토큰) | 5문장 | 템플릿 문장 |
| AI 해설 미리 생성 (F20) | 1 | 하루 약 15건 | digest + 용어 (~2,500토큰) | 3~5문장 | 템플릿 |
| AI 해설 자유 질문 (F20) | 1 | 질문마다 | 근거 (≤ 3,000토큰) | ≤ 400토큰 | 안내 문구 |

모두 로컬 gemma3로 처리, **API 비용 0**. 전문 대신 가이던스 문단 추출(정규식·키워드)을 먼저 코드로 한다.

### 8.1 AI 해설 설계 (F20, 로컬 sLLM)

- **하드웨어**: Mac mini M4, 16GB, SSD 512GB. 수집 작업, Streamlit(market·air), Cloudflare Tunnel이 함께 돈다.

| 용도 | 모델 | 메모리(4비트, 대략) | 이유 |
|---|---|---|---|
| 실시간 자유 질문 | `gemma3:4b` | 약 3~4GB | 상주 가능, 응답 속도 우선 |
| 미리 생성 (매일 07:30) | `gemma3:12b` | 약 8~9GB | 품질 우선. 끝나면 즉시 내림(`keep_alive=0`) |
| 사용 안 함 | `gemma3:27b` | 약 17GB 이상 | 16GB에 올라가지 않음 |

- **속도**: 4b 400토큰 답변 약 10~15초(추정). **설치 후 `ollama run gemma3:4b --verbose`로 실측해 갱신.**
- **실행 위치**: Ollama는 **macOS에 직접 설치**(Docker는 Metal GPU를 못 씀). 컨테이너는 `http://host.docker.internal:11434`로 호출(compose에 `extra_hosts` 설정 완료).
- **근거 범위**: `digest.md`, `glossary.yaml`, 현재 화면 JSON뿐.
- **숫자 규칙**: 답변 속 숫자를 근거 자료와 대조, 없는 숫자가 있으면 답변을 버린다.
- **범위 제한**: 매수·매도·비중·목표가 질문은 거절 후 관련 지표 안내.
- **운영 한도**: 세션당 하루 10문항, 전체 600문항, 질문 500자, 답변 400토큰, 60초 제한, `OLLAMA_NUM_PARALLEL=1`, 대기열 최대 3건.
- **용량 (하루 방문 100명)**: 피크 시간당 질문 60건 × 15초 → 가동률 약 25%, 평균 대기 약 5초. 동시 1건 + 대기열 3건으로 충분. 50%를 넘으면 재검토.
- **보안**: Ollama 포트는 외부에 열지 않는다. 사용자 입력은 도구 실행 권한이 없다.
- **평가**: 질문 30개 골든 세트로 근거 일치율·거절 정확도 측정.

### 9.1 비로그인 개인 설정 (F21)

| 방식 | 동작 | 저장 위치 | 기기 간 이동 | 개인정보 | 판단 |
|---|---|---|---|---|---|
| A. 브라우저 자동 저장 | 자동 저장·복원 | localStorage | 안 됨 | 없음 | **기본** |
| B. 설정 코드 | 무작위 코드(예: `K7QM-2XPA-9TRD`)로 복원 | 서버 SQLite (코드 해시 + 설정 JSON) | 됨 | 없음 | **채택** |
| C. 설정 링크 | 설정을 URL 쿼리에 | URL | 됨 | 없음 | 보조 |
| D. 아이디·비밀번호 | 가입 후 로그인 | 서버 | 됨 | **있음** | 채택 안 함 |

- D를 채택하지 않는 이유: 개인정보 관리 의무, 비밀번호 재사용 유출 위험, 복구 수단이 없어 실익 없음, "회원제" 인상 회피(§12 원칙 7).
- 설정 코드: 12자리(혼동 문자 제외, 약 60비트), 해시만 저장, 1KB 이하, 커버리지 종목만 허용, IP당 분당 5회 제한(IP 미저장), 180일 미사용 시 삭제.
- AI 해설 사용량은 브라우저 저장소의 무작위 ID로 세고, 전체 일일 한도를 함께 둔다.
- Streamlit: `st.query_params`, 브라우저 저장소 컴포넌트는 설치 전 유지 상태·라이선스 확인, SQLite에 `user_settings` 테이블.

### 9.2 비공개 운영 (S0) — Cloudflare Access

**목표**: 공개 전까지 본인만 접속. 앱 코드에는 로그인 기능을 넣지 않고 앞단 Cloudflare에서 막는다. Access는 기기·네트워크가 아니라 **이메일(사람)**을 확인하므로 맥북·휴대폰 어디서든 같은 주소로 접속한다.


**진행 상태**
1. ~~로그인 방법 One-time PIN~~ → 등록 확인 (11-26)
2. ~~Access 애플리케이션~~ → 생성 완료 (11-26): Self-hosted, `market.sielain.com`, 정책 `owner-only`(Allow, 본인 이메일), Accept all identity providers 켬, Cloudflare One Client 끔

## 부록 A. 개발 중 토큰 절약 규칙

- 기준 문서는 이 PLAN.md 하나. Claude Code에는 `CLAUDE.md`만 자동 로드되게 하고, PLAN.md는 필요한 절만 지정해 읽힌다.
- 한 번에 모듈 하나씩 생성·테스트. 전체 재생성 요청 금지.
- 데이터 파일(Parquet, 대용량 JSON)은 Claude에 읽히지 않는다. 필요하면 `python -m pf.jobs.run digest`로 요약을 만들어 그것만 보여준다.
- 화면 수정은 스크린샷 1장 + 바꿀 점 목록으로 요청한다.
- **레이아웃 갱신 규칙**: 화면 구성을 바꾸는 결정이 나오면 `docs/layout_gen.py`를 고쳐 `layout.svg`를 다시 만들고, 머리 표의 레이아웃 버전과 변경 이력을 함께 올린다.
